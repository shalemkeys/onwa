Executive Summary

Onwa is a full-stack web application enabling community book circulation through a Book Passport system. Each physical book carries a digital passport tracking its journey across readers, locations, miles travelled, and community impact. The platform supports multi-role access, queue management, reading logs, live search, impact analytics, and geographic visualization.

Workflow Logic & Process Flows

1. User Lifecycle

Register → INSERT users (role='member', points=0)
↓
Login → Verify MD5 hash → SET session[user_id, user_name, user_role]
↓
Browse Library / Dashboard
↓
├── Join queue → QUEUE table
├── Add to reading log → READING_LOG status='want'
├── Mark reading/finished → UPDATE READING_LOG + books_read += 1
└── Pass book on → PASSPORT_ENTRIES + points += 50
↓
Logout → session.clear()

2. Book Pass-On Workflow

Triggered by: POST /passport//pass-on

  1. Verify current_holder_id == session['user_id']
  2. INSERT into PASSPORT_ENTRIES (book_id, new_holder_id, location, note, miles)
  3. UPDATE BOOKS: current_holder_id, total_miles += miles, total_readers += 1
  4. UPDATE USERS (passer): points += 50, books_passed += 1
  5. INSERT ACTIVITY log entry
  6. Check QUEUE: if next user exists → INSERT NOTIFICATION "Your book is ready!"
  7. Commit transaction

3. Queue Management

Join Queue

POST /queue/join/
↓ Check no duplicate
↓ position = MAX(position) + 1
↓ INSERT queue row
↓ Log ACTIVITY
↓ Return {success: true}

Book Passes On

PASSPORT_ENTRIES inserted
↓ SELECT next in queue
↓ INSERT NOTIFICATION
↓ Badge appears on bell
↓ User clicks → book ready

4. Reading Log Status Flow

want → reading → finished
↓
On 'finished': USERS.books_read += 1 + ACTIVITY logged
↓
API: POST /reading-log/update/ with {status}

5. Live Search (Debounced AJAX)

User types in search box
↓ 300ms debounce
↓ GET /api/search?q=query
↓ SQL: WHERE title LIKE ? OR author LIKE ? LIMIT 8
↓ Return JSON array
↓ Render dropdown (no page reload) + fadeInUp animation

6. Notification Polling

base.html loads → setInterval every 10 seconds
↓ GET /api/notifications/unread → {count: N}
↓ Update bell badge
↓ User clicks → GET /notifications
↓ Display list + UPDATE notifications SET read=1

7. Map View

GET /map
↓ Query books + current_holder location
↓ Match location to UK_COORDS dict (lat/lng)
↓ Pass locations array to Leaflet.js
↓ Render markers → click = popup (title, code, holder)

8. Impact Calculations

MetricFormula
Total BooksCOUNT(books)
Total MilesSUM(passport_entries.miles_travelled)
Total JourneysCOUNT(passport_entries)
CO2 Savedtotal_books × 0.5 kg
Top BooksORDER BY total_miles DESC LIMIT 3

9. Admin Workflow

Add Book

  1. Form: title, author, genre, description
  2. Auto-generate: ONWA- + 4 random digits
  3. Auto-assign cover_color from palette
  4. INSERT books row
  5. Log ACTIVITY entry

Delete Book

  1. POST /admin/delete_book/
  2. Verify role='admin'
  3. DELETE books WHERE id=?
  4. Redirect to /admin

Security

Current Implementation

  • ✓ Session-based authentication
  • ✓ Role-based access control
  • ✓ SQL parameterization (no SQLi)
  • ✓ CORS-safe AJAX (session cookie)

Production Recommendations

  • ⚠ Replace MD5 with bcrypt/argon2
  • ⚠ Add CSRF tokens to all POST forms
  • ⚠ Enforce HTTPS + Secure cookie flag
  • ⚠ Rate-limit login endpoint
  • ⚠ Validate + sanitize all user inputs

Performance

Already Implemented

  • 300ms debounce on live search (80% fewer API calls)
  • LIMIT 8 on search, LIMIT 5 on recent books
  • 10-second notification polling interval
  • Staggered CSS animations (no JS overhead)

Scaling Recommendations

  • Redis cache for notification counts
  • Paginate library (20 items/page)
  • Migrate SQLite → PostgreSQL
  • CDN for static assets
  • Celery + Redis for async notifications
